# ועד הבית

אפליקציית ניהול ועד בית, מתארחת ב-GitHub Pages ומשתמשת ב-Firebase Firestore לסנכרון בין מכשירים.

## פרויקט Firebase

- Project ID: `vaad-af7d3`
- Firebase JavaScript SDK: `13.2.0` via the official modular CDN browser imports
- Authentication: Email/Password, restricted to two authorized email accounts
- Firestore document: `appData/main`
- Data model: schema version 3, documented in `docs/data-model.md`

## הגדרה חד-פעמית ב-Firebase Console

1. בחרו בפרויקט `vaad-af7d3`.
2. ב-Project settings -> General -> Your apps, העתיקו את הגדרות ה-Web app. אם אין Web app, צרו אפליקציית Web.
3. העתיקו את `apiKey`, `messagingSenderId` ו-`appId` אל `src/services/firebase-config.js`. אין להוסיף service-account key לקוד.
4. ב-Authentication -> Sign-in method, הפעילו Email/Password. צרו ב-Authentication -> Users משתמש לכל אחת משתי הכתובות המורשות: zahi.ob4@gmail.com ו-zoharavron@gmail.com.
5. ב-Authentication -> Settings -> Authorized domains, הוסיפו את `rovaitgadsam.github.io`.
6. צרו Cloud Firestore database במצב Production.
7. כללי firestore.rules מגבילים גישה לשתי כתובות המייל המורשות.
8. התקינו Firebase CLI והתחברו:
   ```bash
   npm install -g firebase-tools
   firebase login
   firebase use vaad-af7d3
   firebase deploy --only firestore:rules,firestore:indexes
   ```
10. לאחר פריסת הכללים, רעננו את האפליקציה. בכניסה הראשונה, הנתונים המקומיים במכשיר שבו מתחברים לראשונה יועתקו למסמך הענן אם המסמך עדיין לא קיים.

## מודל סנכרון והגנת נתונים

- המסמך `appData/main` מכיל את מצב האפליקציה המלא.
- לכל כתיבה מוצמד מספר גרסה (`revision`).
- כתיבה מתבצעת ב-Firestore transaction ורק אם הגרסה בענן תואמת לגרסה האחרונה שנקראה.
- אם מכשיר אחר עדכן את הנתונים במקביל, הכתיבה נעצרת ומוצגת התנגשות במקום לדרוס נתונים.
- הנתונים נשמרים מקומית גם כאשר הענן אינו זמין.
- המסמך בענן נוצר פעם אחת בלבד. חיבור מכשיר נוסף אינו מייבא את הנתונים המקומיים שלו מעל נתוני הענן.

## אבטחה

כללי Firestore חסומים כברירת מחדל. קריאה וכתיבה למסמך appData/main מותרות רק לשתי כתובות המייל המוגדרות בכללים. אין לפתוח הרשאות לכלל המשתמשים המאומתים.

## גיבוי

השתמשו בפעולת הורדת הגיבוי באפליקציה לפני חיבור מכשיר נוסף או שחזור. הארכיון ההיסטורי המובנה בקוד אינו חלק ממסמך הנתונים בענן.

## סגירת שנה וארכיון שנתי

- לשונית "ארכיון שנתי" מציגה שנים סגורות לקריאה בלבד, כולל דוחות, תקופות גבייה ותנועות.
- באשף סגירת שנה יש להזין ולאשר את יתרת הקופה בפועל. רק יתרה זו מועברת כיתרת פתיחה לשנה הבאה.
- תנועות ותקופות הגבייה של השנה שנסגרה נשמרות בצילום מצב ארכיוני. השנה החדשה מתחילה עם יומן תנועות ותקופות גבייה ריקים.
- חובות גבייה והוצאות ששולמו אישית נשארים בארכיון. תשלום מאוחר נרשם כהכנסה חדשה בשנה הפעילה עם `collectionYear` לשיוך לשנת הגבייה המקורית.
- לפני סגירה נוצרים גיבוי מקומי וקובץ להורדה. סגירת שנה מחייבת חיבור Firebase פעיל, כדי שהארכיון והשנה החדשה ייכתבו יחד למסמך הנתונים הקיים.
- המיגרציה לסכמה 3 מוסיפה מטא-נתונים לשנת החשבונאות, אך אינה סוגרת שנה ואינה מוחקת תנועות או קמפיינים קיימים.

## רישום הוצאות וחישוב יתרת הקופה

כל הוצאה נחשבת להוצאה מקופת הוועד ומופחתת במלואה מיתרת הקופה, ללא קשר לזהות מי שרשם אותה. השדה ההיסטורי `paidBy` משמש בממשק כ"נרשם על ידי" לצורכי מעקב פנימי בלבד, ואינו משפיע על היתרה, על מאזן הדוחות או על יתרת הפתיחה בשנה החדשה.
